StyleBook - Architectural & Engineering Approach v2.0

High-Level Architectural Patterns, Engineering Rationale, Concurrency Strategies & Financial Design

1. Microservices Architecture & Ocelot Gateway Pattern

Salon marketplaces experience asymmetric query profiles: high-volume read searches (browsing salons across Ramnad, Puduvalasai, Panaikulam) vs. mission-critical transactional writes (slot reservations, OTP verification, wallet debits). We decompose the backend into isolated microservices behind an Ocelot API Gateway running on Port 5000:

  • StyleBook.MasterData.Api (Port 5001): Read-heavy geography, master service taxonomy, and work types. Cached in-memory.
  • StyleBook.Identity.Api (Port 5002): Authentication, JWT tokens, RBAC roles, and territorial allocation enforcement.
  • StyleBook.Salon.Api (Port 5003): Salon profiles, multi-branch management, stylist rosters, custom pricing, and approval workflows.
  • StyleBook.Booking.Api (Port 5004): Slot calculation engine, cart locking, appointment state machine, OTP generation/verification, and reviews.
  • StyleBook.Marketing.Api (Port 5005): Promo coupons, announcements, and compliance notice tracking.
  • StyleBook.Billing.Api (Port 5006 - New): Membership plan subscriptions, booking commission splits, owner wallets, and automated payout batches.

2. Search-to-Booking Relational Integrity Matrix

A primary failure mode in marketplace platforms is booking invalid combinations (e.g. a customer selects a stylist who cannot perform the requested facial, or requests a service at a branch that lacks equipment). StyleBook enforces relational dependency at the API layer:

RELATIONAL INTEGRITY CONSTRAINTS:
1. Branch-First:
   Select Branch (B) 
     → Filter Services (S) where S ∈ branch_service_pricing(branch_id = B, is_offered = true)
     → Filter Stylists (T) where T.current_branch_id = B AND S ∈ stylist_service_durations(T)
     → Fallback: "Any Available Stylist" (assignment handled by Salon Owner)

2. Stylist-First:
   Select Stylist (T)
     → Filter Services (S) where S ∈ stylist_service_durations(T)
     → Filter Branches (B) where B = T.current_branch_id
     → Doorstep Mode: Allowed IF service.is_doorstep_eligible AND T.doorstep_enabled

3. Dynamic Slot Calculation & Cart Holding (Atomic Locking)

Slot Computation Pipeline:

  1. Query salon.stylist_working_hours for targeted date's day-of-week (start time, end time, break hours).
  2. Check salon.stylist_daily_exceptions (approved leave or custom shift).
  3. Query existing confirmed bookings in booking.bookings for target date and stylist.
  4. Calculate total service duration (sum of service durations + doorstep commute buffer if applicable).
  5. Slide time window at 15-minute intervals. If candidate interval overlaps with booked slots or break times, mark Available = false.
  6. Atomic Cart Hold: When customer clicks "Proceed to Checkout", the slot is reserved for **8 minutes** with a temporary hold key. This prevents race conditions where two customers attempt to pay for the same 4:00 PM slot.

4. Financial Escrow & Pre-Funded Wallet Architecture

StyleBook supports both Online and Pay-at-Salon cash bookings with complete commission guarantees:

Payment Mode Flow of Funds Platform Commission Collection Risk Mitigation
Online (Card/UPI/NetBanking) Customer → StyleBook Escrow → Owner Virtual Wallet Directly withheld before crediting Owner Ledger (e.g. 10% commission + 18% GST). Zero risk of default; funds held safely until OTP completion.
Pay-at-Salon (Cash) Customer → Salon Barber (100% Cash in Hand) Debited automatically from Owner's Prepaid Security Wallet upon OTP verification. If wallet drops below -₹2,000 threshold, salon's booking acceptance is automatically locked.

5. Fraud-Proof 6-Digit OTP Handshake Protocol

Appointments cannot be marked completed or debited without physical presence verification:

  • When booking is confirmed, an encrypted 6-digit OTP is generated and displayed on the Customer App.
  • Upon arrival at the salon (or when the mobile stylist arrives at the customer's doorstep), the customer provides the OTP.
  • The stylist enters the OTP in the Management Mobile App.
  • The system validates the SHA-256 hash, changes status from PendingConfirmation / Confirmed to In-Progress, and starts the service timer.
  • Upon service completion, the status updates to Completed, releasing escrow funds to the owner ledger and prompting the customer for dual ratings.
